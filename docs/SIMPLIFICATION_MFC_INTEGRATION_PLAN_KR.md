# DeviceLink 경량화·MFC 운용 통합 작업계획서

- 작성일: 2026-10-18
- 목표: MFC 중심의 한 가지 운용 흐름으로 통신·상태 전이·자동 시험을 설명하고 시연한다.
- 상태: 착수. 아래 체크리스트는 검증이 끝난 항목만 완료 처리한다.

## 1. 범위와 원칙

핵심은 C++20/MFC, 계층별 책임, 통신·프로토콜, 멀티스레드, 자동 시험이다. Unreal은 필요한 장비 시각화와 고장 재현을 담당하고 AI는 선택적인 매뉴얼 설명을 담당한다.

- UI → Application → Core → Protocol/Transport 및 Infrastructure 경계를 지킨다.
- MFC에서 소켓·SQLite·LLM HTTP를 직접 호출하지 않는다.
- 작업 스레드 → 이벤트 큐 → PostMessage → UI 스레드 방식으로 결과를 표시한다.
- 기존 사용자 변경과 Unreal 자산을 보존한다. 용량만 보고 자산을 삭제하지 않는다.
- 기존 버튼과 자연어 요청은 같은 Application 명령 경로를 사용한다.
- 새로운 웹 UI, 벡터 DB, 별도 Agent 프레임워크를 추가하지 않는다.

| Unreal 실행 | UnrealEditor.exe -game | 배포용 가상장비 EXE 우선, 개발 실행 방식은 별도 유지 |

## 3. 목표 화면

| 위치 | 내용 |
| --- | --- |
| 상단 | 대상 장비·연결·장비 상태·고장·Telemetry 경과 시간·선택적 LLM 상태 |
| 운용 탭 | 전원·초기화·Pan/Tilt·조이스틱·실제/목표 각도·온도·전압 |
| 시험 탭 | 고장 주입·응답 지연·무응답·시나리오·Replay |
| 이력 탭 | 이벤트·알람·시험 결과·진단 보고서, 상세 패킷은 하위 영역 |
| 우측 요청 패널 | 자연어 입력·해석한 동작·실행 상태·결과·매뉴얼 근거·선택적 LLM 설명 |
| 접힌 설정 영역 | 주소·포트·재접속·Heartbeat 임계값 등 상세 설정 |

자연어 요청은 입력 → 해석 → 검증 → 실행 → 관측 결과 순서로 처리한다. 모호한 요청·부정문·상충 명령은 실행 전에 거절하거나 명확화를 요청한다. 전송 성공과 실제 동작 완료를 구분한다. 진단 질문은 장비 상태를 바꾸지 않는다.

## 5. 검증과 변경 관리

- 각 단계에서 관련된 C++/Python 회귀 시험을 수행한다.
- 자연어는 부정·상충·불완전 각도·미지원 요청을 반드시 시험한다.
- 진단은 새 Telemetry, 동일 장비, 고장 전후 관측과 보고서 저장을 확인한다.
- 모델 실패가 규칙 기반 관측·보고서·수동 제어를 막지 않아야 한다.
- 기능별 작은 변경으로 진행하며 테스트 실패를 해결한 뒤 다음 단계로 이동한다.
- 용량·시작 시간·모델 지연은 실측값과 측정 조건을 남긴다.
