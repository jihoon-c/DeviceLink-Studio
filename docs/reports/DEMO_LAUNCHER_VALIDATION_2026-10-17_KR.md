# 시범운영 EXE 검증

2026-10-18 MFC 탭·요청 패널 개편 후에는 빌드와 C++ 5개·Python 39개 회귀 시험을 통과했다. 공용 컨트롤 초기화 보강 후 실제 화면 재검증은 사용자 Esc로 중단됐다. 아래 3D·LLM 시연 결과는 MFC 화면 개편 전의 기록이며 개편된 화면의 시각·입력 검증을 대신하지 않는다.

## 구성

프로젝트 루트의 `DeviceLinkDemo.exe`는 C++20 Win32 실행 파일이다. 프로젝트의 Python 가상환경으로 운영 창을 시작한다. 운영 창의 준비·진단·종료 작업은 별도 작업 스레드에서 수행하고, 상태 이벤트 큐를 통해 UI 스레드에 전달한다.

장비 접근은 기존 네이티브 브리지와 Application 계층을 사용한다. MFC는 `--demo` 모드에서 시연용 설정·SQLite를 사용하고 기존 연결 동작을 UI 스레드에서 실행한다. `--demo-hidden`은 자동 검증용이다.

## 통과한 시험

| 시험 | 결과 |
| --- | --- |
| C++ EXE·MFC·브리지 Release 빌드 | 통과 |
| EXE `--check`로 필수 파일과 런타임 확인 | 통과, 종료 코드 0 |
| 기존 Ollama·Unreal을 재사용한 EXE `--smoke` | MFC 자동 연결, 실제 로컬 LLM 진단, FAIL→PASS |
| Ollama·Unreal이 모두 꺼진 상태의 EXE `--smoke` | 세 프로그램을 새로 실행하고 실제 고장 진단·복구 통과 |
| 시범운영 종료 | 런처 소유 프로세스 및 하위 프로세스 잔류 0건 확인 |
| 운영 조정·소유권·취소·모드·첫 Telemetry 대기·고장 해제 회귀 시험 | 9/9 통과 |
| 기존 MCP·SDK·PDF·보고서 회귀 시험 | 25/25 통과 |
| 2026-10-18 3D·MFC·로컬 LLM 동시 실행 | 두 창 정상 응답, 자동 연결 및 Ready 확인 |
| 3D 장비 짐벌 이동 및 실제 모델 고장 시연 | 30°/-10° 도달, LLM 약 7.9초, FAIL→PASS, 보고서 저장 |

실제 모델은 Ollama `qwen3:4b`이며 외부 API 키를 사용하지 않는다. 시험 결과는 `artifacts/demo/check-result.json`, `artifacts/demo/smoke-result.json`, 로그는 `artifacts/demo/launcher.log`에 저장한다. 진단 보고서는 `artifacts/demo/reports/`에 저장한다.

## 발견 및 반영

- 단순 프로세스 종료만으로는 Ollama의 `llama-server.exe`가 남는 문제가 발견되었다. 런처 소유 프로세스를 `KILL_ON_JOB_CLOSE` Windows 작업 그룹에 넣고 하위 프로세스도 정리하도록 변경했다. 실제 자식 프로세스를 생성해 종료를 확인하는 회귀 시험을 추가했다.
- Unreal 엔진 로그와 프로세스 stdout을 같은 경로에 기록하면 로그 파일이 중복 생성됐다. `unreal.log`와 `unreal.process.log`로 분리했다.
- 다른 Unreal 프로젝트가 실행 중인 상태에서 3D 장면을 함께 로딩하면 메모리가 부족했다. 기본값은 백그라운드 Unreal 통신 모드로 정하고, 3D 화면은 운영 창에서 선택·재준비하도록 했다. 3D 장면의 렌더링 품질·성능은 이 시험의 통과 항목이 아니다.
- 기존에 실행 중인 서버를 재사용한 경우 해당 서버는 종료 대상으로 등록하지 않는다. EXE의 프로젝트별 뮤텍스는 운영 창의 중복 실행을 방지한다.
- 2026-10-18 3D 실행에서 TCP 포트가 열린 뒤에도 첫 프레임 셰이더 준비가 이어져 첫 Telemetry가 시간 초과되는 현상을 확인했다. 전원·초기화 전에 첫 Telemetry 응답을 최대 120초 동안 재시도하도록 보강했다. 시간 초과를 두 번 재현한 뒤 정상 응답을 받는 회귀 시험을 추가했다.
- RTX 8GB 환경에서 기존 고품질 3D 장면과 로컬 모델을 동시에 실행하면 GPU 사용률이 98~100%에 이르고 모델 응답이 시간 초과됐다. 시연용 실행 인수에 레이 트레이싱 비활성화, 30FPS, 75% 렌더링 해상도, 낮은 GI·반사·그림자·텍스처 품질을 적용했다. 원본 Unreal 프로젝트의 그래픽 설정은 수정하지 않는다.

## 2026-10-18 최종 3D 검증

부하 조정 후 실제 3D 프로세스와 MFC 창이 응답하는 상태에서 별도 브리지로 짐벌을 30°/-10°까지 이동했다. MotorStall 주입 후 Ollama가 약 7.9초에 매뉴얼 근거 제안을 생성했고, 고장 해제 전 FAIL·해제 후 PASS를 관측했다. 이후 0°/0°로 복귀하고 Ready·고장 없음의 최신 Telemetry를 확인했다. 검증 후 운영 창·3D·MFC는 사용 가능한 상태로 유지했다.

상세 결과: `artifacts/demo/visual-validation.json`. 진단 보고서: `artifacts/demo/reports/f611ade2bf7a4ae89cc2a7e1cc3fb001.json` 및 `.md`. 이 검증은 실행·통신·진단 동작 확인이며, 장면의 시각적 품질이나 목표 FPS 유지 여부를 보증하지 않는다.

## 사용 조건

EXE만 복사한 독립 배포본이 아니다. 프로젝트의 모델·Python 가상환경·Unreal 프로젝트·빌드 결과가 함께 필요하다. `scripts/Build-DemoLauncher.ps1`로 실행 파일을 재생성할 수 있다. 실제 사용 순서는 README의 시범운영 절차를 따른다.
